# 🔐 Security Policy

At ResiliNet, security and responsible vulnerability disclosure are important priorities. We appreciate the cybersecurity community's efforts to help keep the project and its users safe.

## 🛡️ Supported Versions

Security updates are intended for the latest version of ResiliNet available on the `main` branch and the latest published release.

| Version | Supported |
|---|---|
| Latest release | ✅ Yes |
| Older releases | ❌ No |

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability in ResiliNet, please report it responsibly.

**⚠️ Please do not disclose security vulnerabilities through public GitHub Issues.**

Instead:

1. 🔍 Open the repository's **Security** tab.
2. 🔒 Select **Report a vulnerability** if private vulnerability reporting is enabled.
3. 📝 Provide a clear description of the issue and steps to reproduce it.
4. 📎 Include relevant logs, screenshots, or proof-of-concept details where safe.

If private vulnerability reporting is unavailable, contact the repository maintainer privately through their GitHub profile.

## 📋 What to Include in a Report

Please include:

- 📝 A description of the vulnerability.
- 🎯 The affected component or endpoint.
- 🔄 Steps to reproduce the issue.
- ⚡ The potential security impact.
- 💡 Any suggested mitigation or fix.
- 📎 Supporting evidence, if available.

## 🤝 Responsible Disclosure

Please follow these guidelines:

- ⏳ Allow the maintainer reasonable time to investigate and address the issue before public disclosure.
- 🔐 Avoid accessing, modifying, or deleting other users' data.
- ⚖️ Do not perform testing against systems or accounts you do not own or have permission to test.
- 🚫 Do not conduct denial-of-service attacks or other disruptive testing.
- 🤫 Do not publicly share sensitive information discovered during testing.

## 🎯 Scope

Security reports may include issues involving:

- 🔑 Authentication and session management.
- 👤 Authorization and access control.
- 🌐 API endpoint security.
- 🔍 Sensitive data exposure.
- 💉 Input validation and injection vulnerabilities.
- 🗄️ Database access and configuration.
- ☁️ Cloudflare deployment and application security.

## 🔧 Response and Resolution

The maintainer will review submitted reports, investigate valid findings, and work toward an appropriate fix.

Response and resolution times may vary depending on the severity and complexity of the issue.

## 🙏 Acknowledgements

Thank you for helping improve the security of **ResiliNet** and protecting its users.

**Stay safe. Build securely. 🌐🔐**
